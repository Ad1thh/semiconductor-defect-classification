Literature Survey (Part 1)

[1] Saqlain et al. (2019)

A Voting Ensemble Classifier for Semiconductor Wafer Defect Pattern Identification

IEEE Access, vol. 7, pp. 100415–100427

Summary

Proposed a voting ensemble-based machine learning approach combining multiple classifiers to identify wafer defect patterns and boost classification reliability.

Limitations & Gaps

Ensemble models require high computational resources and inference latency. Not optimized for lightweight real-time or edge deployment.

[2] Nakazawa & Kulkarni (2018)

Wafer Map Defect Pattern Classification using Convolutional Neural Networks

IEEE Trans. Semicond. Manuf., vol. 31, no. 2

Summary

Applied CNN deep learning with hierarchical feature extraction directly from wafer maps, eliminating manual feature engineering.

Limitations & Gaps

Conventional deep CNNs are computationally intensive, causing high memory footprints unsuitable for low-latency edge deployment.

Speaker Note: We reviewed existing literature on wafer defect classification. Saqlain et al. utilized voting ensemble methods which improved classification accuracy but lacked real-time edge execution. Nakazawa & Kulkarni proved CNN effectiveness for spatial feature learning, but conventional CNNs suffer from heavy parameter overhead.
03 / 10

Literature Survey (Part 2)

[3] Howard et al. (2019)

Searching for MobileNetV3

Proc. IEEE/CVF Int. Conf. Comput. Vis. (ICCV)

Summary

Introduced MobileNetV3, combining hardware-aware NAS with depthwise separable convolutions for efficient mobile vision execution.

Limitations & Gaps

General-purpose lightweight architecture; not evaluated or adapted for semiconductor wafer defect spatial structures. Domain adaptation is essential.

[4] Im et al. (2021)

Lightweight Deep Learning Architecture for Real-Time Wafer Defect Pattern Classification

IEEE Trans. Ind. Electron., vol. 68, no. 9

Summary

Proposed lightweight deep learning specifically emphasizing model complexity reduction for real-time industrial applications.

Limitations & Gaps

Lacks hardware-agnostic runtime optimization (ONNX) and an end-to-end pipeline connecting preprocessing, model export, and CLI inference.

Speaker Note: Moving to lightweight architectures, MobileNetV3 offers high efficiency but needs domain adaptation for wafer maps. Im et al. addressed real-time constraints but did not provide open ONNX runtime deployment or automated dataset parsing pipelines. Our project bridges these exact gaps.

Problem Statement

Manual Inspection Limitations

Traditional human visual inspection in semiconductor fabrication is slow, expensive, inconsistent, and highly error-prone under high-throughput production.

Complex Defect Spatial Patterns

Wafer defects display complex geometric spatial distributions (Center, Donut, Edge-Loc, Edge-Ring, Loc, Random, Scratch) requiring specialized spatial feature learning.

Legacy Dataset Bottlenecks

Industrial datasets like WM-811K exist in legacy pickle formats with indexing quirks and noise, requiring automated preprocessing pipelines.

Real-Time Edge Constraints

Manufacturing lines require low-latency, hardware-agnostic model deployment without dependency on heavy GPU infrastructure during inference.

Speaker Note: Here we highlight the key problem statements: Manual inspection cannot scale, wafer patterns are spatial and complex, raw datasets are legacy pickeled files, and manufacturing demands sub-second, hardware-independent inference on edge units.

Objectives & Project Scope

01

Automated Data Parsing & Standardization

Develop a robust Python pipeline to load legacy LSWMD.pkl (811,472 records), apply compatibility patches, and convert wafer arrays into standardized 224×224 8-bit grayscale images across 8 defect classes.

02

Lightweight Deep Learning Transfer Learning

Fine-tune MobileNetV3-Small using PyTorch transfer learning with depthwise separable convolutions, Adam optimizer (lr=3e-4), and Cross-Entropy loss for efficient spatial classification.

03

Stratified Data Partitioning & Evaluation Setup

Establish a rigorous 70% Train, 15% Validation, and 15% Test stratified dataset split to ensure balanced representation across all wafer defect categories.

04

Hardware-Agnostic ONNX Optimization

Export trained PyTorch model weights to open model.onnx format with opset 12 and dynamic batch size support for hardware-independent cross-platform execution.

05

Standalone Production CLI Engine

Create a lightweight single-image inference runner (run_inference.py) using ONNX Runtime for CPU/edge deployment with top-3 confidence scoring.

Speaker Note: Our primary objectives cover the full pipeline: standardized data conversion from raw pickle, fine-tuning MobileNetV3-Small, stratified dataset splitting, exporting to ONNX format, and building a standalone inference CLI tool.

Proposed System Architecture

STAGE A

Data Preprocessing Pipeline

  • Raw LSWMD.pkl (811,472 records)
  • Custom Pandas unpickle patch
  • Resize to 224×224 Grayscale
  • 70% / 15% / 15% Stratified Split
STAGE B

Model Fine-Tuning

  • Backbone: MobileNetV3-Small
  • Depthwise Separable Convs
  • Custom 8-Class Linear Classifier
  • Adam (lr=3e-4) + Cross-Entropy
STAGE C

ONNX Optimization

  • PyTorch to ONNX Export
  • Opset 12 Specification
  • Dynamic Batch Axis
  • Optimized model.onnx (<10MB)
STAGE D

Edge Inference Engine

  • run_inference.py CLI
  • ONNX Runtime CPU Execution
  • Top-3 Confidence Scores
  • Industrial Fab Integration

Environment, Tools & Infrastructure

Software Stack & Deep Learning Frameworks

  • OS & Tools: Windows 10/11 / Linux (Ubuntu 20.04+), VS Code / PyCharm, Git
  • Programming Language: Python 3.7+ (Tested on Python 3.14)
  • DL & Deployment: PyTorch (torch, torchvision), ONNX (onnx), ONNX Runtime (onnxruntime)
  • Data & CV: OpenCV (opencv-python), Pillow (PIL), NumPy, Pandas, Scikit-learn
  • Visualization & Utils: Matplotlib, Seaborn, Tqdm

Hardware Infrastructure

  • Training Hardware: NVIDIA GPU (CUDA support) for efficient transfer learning fine-tuning.
  • Target Inference Hardware: Standard x86 CPU / Industrial ARM Edge Devices (Raspberry Pi / Jetson).
  • Memory Footprint: System RAM ≥ 8GB; Model binary size < 10 MB.
  • Storage: SSD storage for dataset image caching (output/Dataset/).
Speaker Note: The software stack relies on PyTorch for model training and ONNX Runtime for edge inference. For hardware, initial training utilizes NVIDIA GPUs, while target deployment runs efficiently on standard industrial CPUs without expensive GPU hardware.
